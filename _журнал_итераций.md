# Журнал итераций с AI-инструментом

Рабочий журнал: что реально происходило при разработке прототипа. Инструмент — Claude Code (агент в десктоп-приложении). Оформление для сдачи решим отдельно.

## Итерация 1. Постановка задачи (09.11.2026)

**Запрос команды:** сделать работающий прототип по требованиям ПР3–ПР4, показать только основной функционал MVP. Дизайн — в духе старых экранов Тинькофф (понятный интерфейс для небольшого регионального банка). Показ с ноутбука, хранение локально.

**Что предложил AI до начала разработки:**
- взять сквозной сценарий UC-01 + UC-02: кабинет клиента, движок решения, экран андеррайтера;
- реализовать Must-требования FR-01, 02, 03, 05, 08, 09, 10, 11, 13, 15–21, 28, 30, 40 и Should FR-04, 06, 14, которые нужны для демонстрации;
- не включать управление правилами, отчёты, рабочие места менеджера и комплаенса;
- заменить внешние системы заглушками: пять тестовых компаний, у каждой свой исход;
- технически — одна HTML-страница без сервера, данные в localStorage.

Команда согласовала объём: клиент + андеррайтер.

## Итерация 2. Первая реализация

Созданы файлы `data.js` (справочники и правила), `store.js` (хранилище), `engine.js` (движок UC-02), `app.js` (экраны), `styles.css`, `index.html`.

## Итерация 3. Первый прогон и найденные проблемы

Проверены все пять тестовых клиентов, загрузка файлов, подпись, решение андеррайтера и защита от дублей. Логика исходов отработала верно. Найдены ошибки и несоответствия:

1. Пока заявка проверяется, экран клиента не обновлялся: был виден только статус «Получена», затем сразу решение. Промежуточный статус «На проверке» (FR-10) клиент не видел.
2. После решения последний шаг статуса оставался «текущим» (жёлтым), а не завершённым.
3. SMS с кодом подписи исчезало через 5 секунд. На демо после ошибки ввода код уже не посмотреть.
4. Размер маленьких файлов показывался как «0,0 МБ».
5. В форме отказа андеррайтера в выпадающий список попадал длинный текст для клиента, он обрезался.
6. Журнал заявки засорялся записями автосохранения на каждом шаге мастера.
7. Список недостающего (FR-05) не обновлялся сразу после отметки согласия.
8. На ширине меньше ~1000 px шапка переносилась на две строки.

## Итерация 4. Исправления

- Экран перерисовывается после каждого шага движка; у клиента появилась строка «что сейчас происходит» со спиннером.
- После решения все шаги статуса отмечаются как завершённые.
- SMS с кодом висит, пока открыто окно подписи, и закрывается после подписи или отмены.
- Размер файлов меньше 1 МБ показывается в КБ.
- У андеррайтера короткие названия причин, а под списком — «Клиент увидит: …».
- Записи автосохранения убраны из журнала.
- Список недостающего пересчитывается при отметке согласия.
- Для экранов до 1000 px добавлена компактная шапка.

## Итерация 5. Повторный прогон

Повторно пройдены сценарии «Хлебный двор» и «Северный склад». Новые находки:

1. Выбранная андеррайтером причина отказа не сохранялась: обработчик записывал значение только по событию ввода текста, а выпадающий список отправляет событие выбора. Клиент получал не ту причину.
2. В журнале согласия записывались техническими кодами («pd», «bki»).
3. На узком экране переносилась ссылка «Сбросить демо».

## Итерация 6. Исправления и проверка

- Причина отказа сохраняется по событию выбора; проверено, что клиент видит именно выбранный текст.
- Согласия в журнале названы по-человечески.
- Ссылки в шапке не переносятся.

Итог: все сценарии из README проходят.

## Итерация 7. Замечание команды по дизайну

**Замечание:** интерфейс слишком буквально повторяет Тинькофф — жёлтые кнопки с чёрным текстом, белые сильно скруглённые карточки без рамок, чёрные «таблетки» выбора. Нужен свой стиль.

**Что изменено:**
- основной цвет — глубокий сине-зелёный (#0B6E5F), тёплый янтарный только для текущего шага и важных подсказок;
- шапка залита основным цветом, разделы переключаются вкладками с подчёркиванием;
- кнопки — залитые с белым текстом и умеренным скруглением, второстепенные — с обводкой;
- карточки с тонкой рамкой и меньшим скруглением, поля ввода с рамкой;
- шаги мастера — нумерованные кружки с галочкой у пройденных;
- свой логотип: квадрат из четырёх частей с закрашенной «четвертью» — отсылка к названию «Кварта».

Проверены экран входа, мастер заявки, карточка заявки и рабочее место андеррайтера; логика не менялась.
